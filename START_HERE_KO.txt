AirPods Widget 시작 순서
========================

1. verify_windows.bat
   - Python/의존성 설치
   - 28개 단위 테스트
   - Python/QML 정적 검사
   - 실제 Qt 엔진 QML 로딩 검사

2. run_demo_windows.bat
   - AirPods 없이 디자인, 크기, 테마, 트레이 팝업, 미디어 버튼,
     알림 볼륨과 테스트 MP3를 먼저 확인

3. build_windows.ps1 실행 후 관리자 PowerShell에서 install_msix.ps1
   - 관리자 권한 PowerShell에서 globalMediaControl 권한이 있는 Windows 패키지 설치
   - 설치 후 시작 메뉴의 AirPodsWidget 실행
   - AirPodsWidget.msix를 직접 더블클릭하지 말 것 (서명 전 파일)

4. run_windows.bat
   - AirPods Pro 3를 Windows에 연결한 상태로 portable BLE 실행

5. 필요할 때 build_windows.ps1
   - 프로젝트 루트의 AirPodsWidget.exe, _internal, AirPodsWidget.msix 갱신

GitHub에서 새로 받은 경우
-------------------------
- `assets\low_power_warning.mp3`는 재배포 권한 문제로 저장소에 포함하지 않습니다.
- 권한이 있는 MP3를 해당 경로에 넣은 뒤 `verify_windows.bat`을 실행하세요.
- `.venv`, `_internal`, `build`, `dist`, 실행 파일, 캡처 PNG, 인증서와 로그는 업로드하지 않습니다.

실행 파일
---------
프로젝트 루트의 AirPodsWidget.exe

미디어 기능까지 사용할 주 실행본:
프로젝트 루트의 AirPodsWidget.msix

`dist\AirPodsWidget`와 `build\msix-staging`는 빌드 임시 폴더입니다. 별도의 ZIP이나 다른
실행 폴더는 사용하지 않습니다.

일반 portable EXE에는 Windows의 `globalMediaControl` 패키지 권한을 붙일 수 없습니다.
따라서 미디어 기능은 반드시 MSIX 설치본을 실행해야 합니다.

로그 위치
---------
%LOCALAPPDATA%\AirPodsWidget\app.log

중요
----
- 별도 Bluetooth/커널 드라이버를 설치하지 않습니다.
- Test Mode나 Secure Boot 설정을 변경하지 않습니다.
- 저전력 알림은 BLE의 10% 단위 제한 때문에 첫 10% 표시에서 울립니다.
- 업로드한 MP3 알림음은 설정의 "테스트 알림"으로 볼륨을 확인할 수 있습니다.
